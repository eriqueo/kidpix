## 1. Make the browser test signal trustworthy

User journey: As a maintainer preparing a release, I can run one Chromium smoke path
and trust that a failure identifies a current kid-visible regression rather than an
obsolete expectation or positional selector.

Acceptance checks:

- DONE: every Chromium failure or blanket skip was classified and either repaired or
  skipped per-test with a tracked reason (`tests/e2e/tool-switching.spec.ts` names the
  unimplemented remember-last-subtool feature).
- DONE: startup, Pencil drawing, undo, stamp choice, and narrow-screen drawers are
  covered; semantic selectors replace tail indexes.
- OPEN: one named smoke command that runs only the deterministic subset (today the whole
  Chromium project is the smoke path, ~50 s locally). Add it only if the full run becomes
  too slow or flaky to gate on. See [playwright.config.ts](../playwright.config.ts).

## 3. Prove saved drawings reopen for continued editing on iPad

User journey: As a child using the iPad, I can save an editable drawing to Files, open it
later through the same obvious Open control, and continue drawing. PNG remains an explicit
flattened export/import format.

Acceptance checks:

- AUTOMATED: toolbar Save writes versioned `.kidpix` v1 with exact 1300×650
  pixels and frame state; Open dispatches `.kidpix` or ordinary images by file type; Export
  PNG is separate. The iPad-sized Chromium journey saves, clears, reopens exact pixels,
  continues through the touch Pencil path, and round-trips PNG.
- AUTOMATED: file-capable touch browsers use the native share sheet only after
  `navigator.canShare({files})`; cancel/rejection exposes a separate Download action rather
  than automatically performing a second write.
- REPAIR IMPLEMENTED, OPEN DEVICE RETEST: Open File no longer gives iPadOS an extension/MIME
  filter that disables `.kidpix`; strict parsing still happens at the app boundary and Save
  still makes at most one external effect. Rerun items 16–20 and record exact filenames if
  duplication remains.

## 4. Prove custom Hidden Pictures on the target iPad

User journey: As a child, I can open **My Hidden Pictures**, add a photo, immediately reveal
its pixelated version, and later use or delete it from the same simple library.

Acceptance checks:

- AUTOMATED: the touch-sized Chromium journey chooses a normal PNG through the real file
  picker, verifies monochrome processing, visible confirmation, content-keyed deduplication,
  IndexedDB hydration after reload, and an actual Hidden Pictures reveal stroke.
- AUTOMATED: custom records use version 1, retain only the processed PNG, and form an
  AUTO-MANAGED queue capped at 20. A distinct picture at the limit atomically evicts the
  oldest custom entry; unavailable storage falls back to a bounded session queue and says so.
- REPAIR IMPLEMENTED, OPEN DEVICE RETEST: **My Hidden Pictures** owns add/use/delete and immediately
  selects a newly processed photo. Photos or Camera is the acceptance path and Files is not
  required. Rerun items 12–15.
